# UI 调试



双击项目根目录的 **UI调试.cmd**。它会从源码编译 Debug 版本并打开调试控制面板，不生成安装包或 zip。



控制面板可以：



- 打开真实的托盘弹窗，或点击新增的“AetherDrop · UI 调试”托盘图标。

- 模拟接收邀请，手动点击接受、拒绝或关闭。

- 直接模拟动态传输，查看右侧飞入、按模拟字节实时计算的速度、环形进度和完成状态。

- 暂停、继续、直接完成、模拟失败、模拟超时及清空弹窗。



关闭控制面板会退出本次调试并移除调试托盘图标。它可以和已安装的正式版同时运行。



## 源码与修改



主要界面位于 `app/client/TrayWindow.cs`、`ReceiveWindow.cs`、`FloatingCard.cs`。

弹窗采用实际尺寸布局：托盘 244 × 208，接收/进度 302 × 142（DIP）。

字号、图标、间距在各控件内单独设置，没有整体缩放容器。



修改后关闭调试窗口，再次双击入口即可重新编译。首次启动需要本机 .NET 8 SDK；

当前开发入口会自动使用 `%LOCALAPPDATA%\Microsoft\dotnet-sdk`。



也可以在项目目录的 PowerShell 中执行：



```powershell

./scripts/debug-ui.ps1

```



可选使用 .NET watch 监视源码变化。支持的修改会热重载，需要重启时按终端提示操作；

不同种类的 WPF 修改可能仍需关闭窗口并重新运行。



```powershell

./scripts/debug-ui.ps1 -Watch

```



## 模拟边界



调试入口使用 `--ui-debug`，绕过正式版的单实例转发、系统注册和后台启动流程。

设备名、接收开关等设置仅保存在内存，不读取或写入正式设置。模拟文件不会写入磁盘。

它不连接后台服务、不启动 AirDrop 引擎、不监听蓝牙、不切换网卡，也不发送系统接收通知。



调试模式使用动态变化的模拟字节流，显示值不是实际网卡或 AirDrop 速率；实际运行时同一显示组件读取引擎的真实已接收字节数。暂停或没有新字节时，速率会降至 0。

这是界面和交互调试，不测试真实 AirDrop 互传。



## 离线验证



```powershell

. ./scripts/dev-env.ps1

dotnet run --project tests/UiDebug.Smoke/UiDebug.Smoke.csproj -c Debug

```



该检查覆盖调试启动、临时设置、接受和进度、暂停继续、完成、失败、超时、重置，

并验证正式设置、通知协议和开机启动注册未改变。
